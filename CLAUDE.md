



# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

SecondBrain is a study notes summarizer. Users add sources — PDFs, PPTs, YouTube video links and website links — and the app turns them into concise notes that cite where each point came from (for YouTube, the timestamp in the video), generates flashcards for quick revision, and has an AI assistant that answers questions from the saved material. `backend/` is FastAPI + Postgres + Chroma; `frontend/` is React 19 + Vite + TypeScript + Tailwind v4.

Current gaps against that goal (as of 2026-09):
- **Word sources carry no location.** `.docx` has no pages (only Word's layout makes them); the nearest heading would be the only option. PDFs uploaded before page tracking also cite nothing until re-indexed (`scripts/reindex_pdf_pages.py`).
- **PowerPoint search results have no slide number** (a matched chunk that starts mid-slide doesn't contain its marker); summaries and flashcards do cite slides.

**PDF page citations:** `PDFService.extract_pages` → `RAGService.chunk_pages` (same packing as `chunk_text` via the shared `_pack`, but each sentence carries its page) → `chunks.page_start` / `page_end` and the same keys in Chroma metadata. Pages are physical PDF pages, not printed page labels; a chunk crossing a page break (or carrying overlap from the previous page) spans two. `format_pages` renders "p. 12" / "pp. 12–13". PDFs uploaded before this have null pages and behave as before; `scripts/reindex_pdf_pages.py` (dry run by default, `--apply`) rebuilds their chunks and vectors from `uploads/` with backup/rollback, leaving summaries and flashcards as they are. Offline tests: `tests/test_pdf_page_citations.py`.

**Flashcard citations:** `generate_cited_flashcards` (`app/services/ai/flashcard_service.py`) works from the stored chunks, labelled `[S0]`, `[S1]`, …; the LLM returns a `source` label per card, validated against the batch it was shown (anything else → no citation, card kept). `build_chunk_citations` turns a chunk into a citation from stored data: YouTube `("02:05", timestamp url)`, website `(page title, url)`, PPTX `("Slides 3–4", None)` from `[Slide N]` markers tracked across chunks, PDF `("p. 12", None)` from the chunk's stored page range, DOCX `None`. Saved on `flashcards.source_label` / `source_url` at generation time; old cards stay null until regenerated. Coverage is enforced in code, not the prompt (the model favours the start of whatever it sees): short sources are split into `ceil(count/3)` consecutive groups, long ones sampled evenly, picks taken round-robin and returned in source order. Documents without chunks fall back to `generate_flashcards(doc.content)`. Offline tests: `tests/test_flashcard_citations.py`.

**Summary citations:** `generate_cited_summary` (`app/services/ai/summary_service.py`) labels each stored chunk `[S0]`, `[S1]`, … and the LLM cites labels, never times, pages or slides; `replace_labels` then swaps each label for that chunk's citation (from `build_chunk_citations`): `[mm:ss](url&t=…)` links for YouTube (`generate_youtube_summary` is a wrapper), "(p. 12)" for PDFs with page ranges, "(Slide 4)" for PowerPoint; several plain citations on one point merge into "(p. 3; pp. 7–8)". Labels matching no chunk (or a chunk without a citation) are dropped. Markdown-escaped labels (`\[S3\]`, which some models write) are matched and replaced too. Keep it that way — don't let the model write locations. Websites, Word files and pre-page-tracking PDFs use the plain `generate_summary`. Summaries are cached in `summaries`, so prompt changes only show after regenerating. Offline tests: `tests/test_youtube_summary_citations.py` (mocked LLM, safe to run).

**Website links:** `POST /api/v1/upload/website {url}` → `app/services/web/`. `url_safety.py` is the SSRF guard: only http/https on ports 80/443, and every resolved address must be public (`is_public_ip`). It runs on the submitted URL and on every redirect hop (redirects are followed by hand, max 5), and `SafeNetworkBackend` re-resolves at connect time and connects to the checked IP (stops DNS rebinding). Keep `follow_redirects=False` and `trust_env=False`, and never use trafilatura's own downloader. Limits: 5 MB, 20 s total. `WebService.extract_article` uses trafilatura for main text + title (reference lists, footnote markers and navboxes are pruned first via `_PRUNE_XPATH`; a short page whose text says "enable JavaScript" counts as JavaScript-only) and raises `WebPageError` (blocked / login_required / javascript_required / no_text / …; `.message` is user-facing, `.status_code` is the HTTP status). Stored as `source_type="website"`, `filename`=page title, `source_url`=final URL, details in `metadata_json`. Re-importing a saved page returns 409 with `detail={message, document_id}` (YouTube does the same for a saved video ID, checked before the transcript fetch; these are the only upload errors whose detail is an object, and `importError` in `api/client.ts` turns them into `DuplicateSourceError`): `url_key` in `web_service.py` defines "same page" and is compared against each website doc's `source_url` and `metadata_json.original_url`, before fetching and again after redirects. Search matches carry `source_type`/`source_url`, and website summaries get a code-built `Source: [title](url)` footer (`append_source_link`). Offline tests: `tests/test_website_ingestion.py` (network, DNS, DB and LLM all mocked, safe to run).

**Merged sets:** 2–8 documents of any type (at most 80,000 characters of `Document.content` together) studied as one: `app/routes/merged_sets.py` (`/api/v1/merged-sets`), models in `app/models/merged_set.py`, generation in `app/services/ai/merged_service.py`. They have their own tables (`merged_sets`, `merged_set_documents` with a `position`, `merged_summaries`, `merged_flashcards`) and never touch the per-document `summaries` / `flashcards`, so a set can't overwrite a document's own study material. Creating a set with exactly the documents of an existing one, in any order, returns that set with `created: false` (the page says it was reopened). Deleting a document removes its membership (ON DELETE CASCADE) and unlinks its merged cards (`document_id` SET NULL); both happen in Postgres, since `Document` has no relationship to these tables. The set then reports `summary_stale` (the summary's stored `document_ids` include a non-member) / `flashcards_stale` (an unlinked card) until regenerated, and it can't be regenerated with fewer than 2 members. Summary: `generate_merged_summary` labels every chunk of every source `[S0]…` across the set, maps long sources batch by batch without mixing two sources in a batch, and `merged_citation` puts the source's number in front of each chunk's citation: "(1: p. 12)", "(2: Slide 4)", "[3: 02:05](url)", "[4](url)" for web pages, "(5)" for Word and page-less PDFs. Plain citations are grouped by source ("(1: p. 3, pp. 5–6; 2: Slide 4)", `join_by_source`), a code-built Sources list at the top maps the numbers to documents, and sources are numbered 1..n over the current members when generated. The merged prompt asks for "Source 2" (never the labels) in sentences and plain-text formulas; `plain_inline_math` also strips `\(…\)`. Flashcards: `allocate_cards` splits the count over the sources by text size (at least 1 each, adding up exactly) and each share comes from `generate_cited_flashcards`; card labels name the source ("Graph_PPT.pdf · p. 12"). Frontend: the Library's Select mode (cards and table rows become checkboxes, sticky bar, Escape leaves) calls `createMergedSet`, and so does the upload area (`UploadZone`) after a multi-file upload: files go one at a time through the normal upload endpoints (a failed or skipped file doesn't stop the rest), a results panel lists each, and when 2–8 uploaded it offers "Create merged set" with their ids in upload order; `onUploadSuccess({ multiple: true })` tells the Library not to close the upload area. `SummaryPage` / `FlashcardPage` take `merged` for `/library/merged/:setId/summary|flashcards`. Offline tests: `tests/test_merged_sets.py` (in-memory SQLite with foreign keys on), `test_merged_summary.py`, `test_merged_flashcards.py`.

`SECOND_BRAIN_PROJECT_CONTEXT.md` holds the product/UI brief (design direction, naming rules, "don't invent endpoints or fake data"). It is partly stale — e.g. it says only PDF upload works and YouTube is "Coming Soon", but PPTX/DOCX/YouTube are implemented end to end. Trust the code over that document.

## Commands

Backend (run from `backend/` — `uploads/` and `vector_db/` are resolved relative to the working directory):

```bash
.venv/Scripts/python.exe -m uvicorn main:app --reload     # API on :8000, docs at /docs
```

Requires `backend/.env` (copy `.env.example`): `DATABASE_URL` (Postgres; the app refuses to start without it), `OPENROUTER_API_KEY`, optional `CHROMA_DIR`, `SQL_ECHO`, `OPENROUTER_MODEL`.

Frontend (from `frontend/`):

```bash
npm run dev        # Vite dev server; proxies /api -> http://127.0.0.1:8000
npm run build      # tsc -b && vite build (this is the type check)
npm run lint       # oxlint
```

Tests: `backend/tests/` contains ad-hoc verification scripts, not a pytest suite (pytest is not installed). Apart from the offline `test_youtube_summary_citations.py`, `test_website_ingestion.py`, `test_office_formats.py`, `test_flashcard_citations.py`, `test_concurrent_generation.py`, `test_youtube_duplicates.py`, `test_ai_error_messages.py`, `test_pdf_page_citations.py`, `test_document_rename.py`, `test_model_setting.py`, `test_reasoning_model_output.py`, `test_error_in_reply_body.py`, `test_summary_retries.py`, `test_merged_sets.py`, `test_merged_summary.py`, `test_merged_flashcards.py` and `test_upload_cleanup.py`, they run against the **live** Postgres, Chroma and OpenRouter, and some mutate data (`test_delete_endpoint_and_cleanup.py` deletes hard-coded document IDs). Don't run them casually; run a single one with `.venv/Scripts/python.exe tests/<file>.py` from `backend/`. There are no frontend tests.

## Backend architecture

- `main.py` loads `.env`, mounts five routers, and calls `init_db()` on startup. There is no Alembic: `init_db()` (`app/database/db.py`) runs `create_all` plus hand-written `ALTER TABLE ... IF NOT EXISTS` statements. Add new columns there as well as on the model.
- Routers live in two places: `app/api/upload.py` (all ingestion) and `app/routes/` (`documents`, `search`, `study`, `merged_sets`). The other files in `app/api/`, and `core/`, `utils/`, `schemas/`, `services/graph|ocr`, `ai/merge_service.py` are empty placeholders.
- **Dual storage.** Postgres holds `documents` (with full extracted text in `content`), `chunks`, `summaries` and `flashcards`. Chroma (`app/database/chroma.py`, collection `secondbrain_chunks`, cosine) holds the vectors. `Chunk.chroma_id` links the two, formatted `"{document_id}-{chunk_index}"`; Chroma metadata carries `document_id`, `filename`, `source_type`, for YouTube `source_url`/`start_seconds`, and for PDFs `page_start`/`page_end`. Anything that creates or deletes chunks must keep both stores in sync — see `_store_document_and_chunks` in `upload.py` (Chroma add then DB commit, with Chroma cleanup on failure) and `delete_document` in `routes/documents.py`.
- **Ingestion flow:** each upload endpoint saves to `uploads/{uuid}.{ext}` (everything after the save runs inside `_removed_on_failure`, which deletes the file if the upload fails, so no orphaned files are left; PDFs are parsed from the in-memory bytes because PyMuPDF keeps a file it failed to parse open while the error is alive, and Windows then refuses the delete; a PDF with images but no text gets `SCANNED_PDF_MESSAGE`, as there's no OCR) → a format service in `app/services/<fmt>/` extracts text → `RAGService.chunk_text` (sentence-packed ~800 chars, 150 overlap; PDFs use `chunk_pages`, see above) → `_store_document_and_chunks`. YouTube skips the file and uses `YouTubeService.pack_transcript_chunks` to keep per-chunk start timestamps. Website links also skip the file (fetch → extract → `chunk_text`). Code targets `youtube-transcript-api` 1.x (instance `.fetch()`).
- **Embeddings:** only through `app/services/embedding_service.py` (single cached `all-MiniLM-L6-v2`). Don't instantiate SentenceTransformer elsewhere.
- **LLM calls:** OpenRouter through the `openai` SDK with `base_url="https://openrouter.ai/api/v1"`. The model is `MODEL_NAME` in `summary_service.py` (imported by the other two): `OPENROUTER_MODEL` from `.env` if set (e.g. a `:free` model for testing), else `openai/gpt-3.5-turbo`; it's read at import, so changing it needs a backend restart, and a non-default model is logged at startup. Reasoning models spend part of `max_tokens` thinking, so every summary/flashcard cap adds `REASONING_ALLOWANCE` (3000); `reply_text` / `check_reply` log replies that still hit the limit (`finish_reason == "length"`), and an empty reply raises `AIGenerationError` ("The AI returned an empty reply…"). OpenRouter sometimes answers HTTP 200 with `{"error": {"code": 503, …}}` and no `choices` (e.g. a provider overloaded); the SDK doesn't raise for it, so `check_reply` raises the matching `openai.APIStatusError` (502 when the code is unusable), which gets the right `ai_failure` message and the flashcard retry rules. Every reply must go through `reply_text` or `check_reply`. Summary calls go through `_complete`, which retries temporary failures (overloaded, 429, 5xx, timeout, connection) up to `TRANSIENT_RETRIES` (2) times with a growing pause, because a map-reduce or merged summary makes several calls and one blip would fail them all; flashcards retry once. OpenRouter's daily free-model cap (`is_daily_limit`: 50 requests a day on an account without credits, `limit_source: openrouter_free_tier_daily`) is never retried and gets `DAILY_LIMIT_MESSAGE`. Offline tests: `tests/test_reasoning_model_output.py`, `tests/test_error_in_reply_body.py`, `tests/test_summary_retries.py`. Each service (`search_service`, `ai/summary_service`, `ai/flashcard_service`) creates its own client. Summary and flashcard generation work on `Document.content` and split it into 3000-char chunks when it is over 6000 chars (summaries map-reduce; flashcards generate per chunk until `count` is reached), and raise `AIGenerationError`, which the routes turn into 502s. Its message is shown to the user as-is, so build it with `ai_failure(e, "...")` (`summary_service.py`): it logs the raw OpenRouter error and maps it to a plain sentence (402 out of credits, 401 bad key, 404 model unavailable, 429 rate limit, timeout, 5xx, …). Search does the same: `generate_answer` raises instead of returning an error string, and `/search` answers 502. The summary and flashcard routes can be hit twice at once (the pages auto-generate when nothing exists, and React StrictMode runs that effect twice in dev), so they take `_lock_document` (a row lock) only around the save, never the LLM call, and re-read before writing; the frontend also shares an in-flight generation request per document (`shareInFlight` in `api/client.ts`).
- **Search** (`GET /api/v1/search?query=`) returns `{query, answer, top_matches[{score, content, document, youtube_timestamp_url, source_type, source_url, location}]}` built from the top 3 Chroma hits (`location`: "02:05" for YouTube, "p. 12" for PDFs with pages, else null).
- **Rename** (`PATCH /api/v1/documents/{id} {filename}`): search results take the name from Chroma metadata, so `rename_document` rewrites `filename` on the document's vectors first, then commits the row, and puts the old metadata back if the commit fails. Whitespace is collapsed; empty or over 255 characters → 400. Summaries already generated keep whatever name they were built with (only website summaries embed it, in the `Source:` footer). Offline tests: `tests/test_document_rename.py`.

## Frontend architecture

- All HTTP goes through `src/api/client.ts` (relative `/api` base, relying on the Vite proxy); response types are in `src/types/index.ts` and mirror the backend dicts by hand, so update both together.
- Routes are defined in `src/App.tsx` under `AppLayout` (sidebar + `<Outlet/>`): `/`, `/library`, `/library/:documentId/summary`, `/library/:documentId/flashcards`, `/library/merged/:setId/summary`, `/library/merged/:setId/flashcards` (the same two pages with `merged`), `/flashcards`, `/settings`. `ChatPage` exists but is not routed. Source-type icons and colours come from `components/library/sourceBadge.tsx` (DocumentCard and the Flashcards hub's document cards still have their own copies).
- `DocumentContext` holds the shared document list for the Sidebar and Home. `SplashScreen` seeds it on first load. `LibraryPage` keeps its own separate fetched copy.
- Styling mixes CSS variables from `src/styles/design-tokens.css` with many hard-coded hex values in Tailwind arbitrary classes.
